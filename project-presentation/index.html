Executive Summary

Από την εγγραφή χρήστη μέχρι την αίτηση, την αξιολόγηση και την πρόσβαση στο Moodle.

Η πλατφόρμα είναι web εφαρμογή σε PHP/MySQL με διακριτά modules ανά ρόλο, εξαγωγές δεδομένων, maintenance mode, ειδοποιήσεις προς διαχειριστές, ροές συγχρονισμού enrollment και ασφαλή διαχείριση αρχείων.

5 ρόλοι χρηστών 16 πίνακες βάσης End-to-end flow από την αίτηση έως το LMS access
Δες το Γενικό Flow REST API και Postman
53,300 Γραμμές κώδικα συνολικά σε PHP, CSS, JS, SQL και τεκμηρίωση
16 Πίνακες στη βάση με 22 foreign keys
5 Ρόλοι με διαφορετικά permissions και διαφορετικά dashboard flows
Realtime admin notifications

Core Modules

  • Admin: χρήστες, reports, ρυθμίσεις συστήματος
  • Recruitment: candidate dashboard, αιτήσεις και statuses
  • Enrollment: LMS sync, full sync και download stats

02

Data Layer

Βάση δεδομένων, πίνακες και μεταξύ τους σχέσεις

16 πίνακες σε 5 domains

  • Users: users
  • Academic: schools, departments, courses
  • Recruitment: periods, announcements, applications, evaluators, form fields, responses
  • Enrollment: lms_access, specialist_enrollments, enrollment_logs
  • System: system_settings, notifications, audit_logs

Πώς συνδέονται

  • school -> department -> course
  • period + school + department + course -> job_announcement
  • job_announcement + candidate -> candidate_application
  • candidate_application -> application_responses/files
  • user + course -> lms_access + specialist_enrollments

Key Fact

Οι 22 foreign keys επιβάλλουν referential integrity και αποτρέπουν orphan εγγραφές στη βάση.

03

Role-Based Access

Τι βλέπει κάθε ρόλος αμέσως μετά το login

admin

Οδηγείται στο module-select και έχει πρόσβαση στο Admin και στο Enrollment module.

hr

Οδηγείται στο module-select και έχει πρόσβαση στο Recruitment και στο Enrollment module.

evaluator

Βλέπει το recruitment dashboard για αξιολόγηση και ενημέρωση αιτήσεων.

candidate / ee_hired

Ο candidate ακολουθεί το recruitment flow, ενώ ο ee_hired αποκτά enrollment dashboard και πρόσβαση στο Moodle.

Guards

Τα admin pages προστατεύονται με admin-only guards, το recruitment ελέγχει επιτρεπόμενους ρόλους και το enrollment είναι διαθέσιμο μόνο στους admin, hr και ee_hired.

04

Γενικό Flow

Τι συμβαίνει από τη δημιουργία λογαριασμού μέχρι την τελική πρόσβαση

1

Ο χρήστης κάνει εγγραφή με validation σε email, τηλέφωνο και ισχυρό κωδικό.

2

Μετά το login δημιουργείται session και γίνεται redirect με βάση τον ρόλο.

3

Ο candidate βλέπει τις ανοιχτές προκηρύξεις και ξεκινά αίτηση τεσσάρων βημάτων.

4

Η αίτηση μπορεί να αποθηκευτεί ως draft ή να γίνει submit μαζί με αρχεία, όπως CV και supporting documents.

5

Με το submit δημιουργείται notification προς όλους τους admins.

6

Admin, HR και evaluator βλέπουν την αίτηση και ενημερώνουν το status της.

7

Ο candidate παρακολουθεί την πορεία μέσα από το Application Status και σχετικό timeline.

8

Αν ο χρήστης γίνει ee_hired, ενεργοποιείται το enrollment flow και η πρόσβασή του στο Moodle.

08

Security & Data Safety

PDO, sessions, sanitization, πολιτική κωδικών και ασφαλής διαχείριση αρχείων

Πού φαίνεται η ασφάλεια στον κώδικα

  • PDO με prepared statements σε authentication, API και enrollment actions
  • Sessions με guards και role checks σε κάθε module
  • htmlspecialchars() για ασφαλή εμφάνιση δυναμικών δεδομένων
  • password_hash() και password_verify() για ασφαλή διαχείριση credentials

Πολιτική ισχυρού κωδικού

  • Τουλάχιστον 8 χαρακτήρες
  • Τουλάχιστον 1 κεφαλαίο, 1 πεζό και 1 αριθμός
  • Τουλάχιστον 1 special character από προκαθορισμένο επιτρεπόμενο σύνολο
  • Έλεγχος τόσο client-side όσο και server-side

Επιπλέον προστασία αρχείων

Τα αρχεία αιτήσεων κατεβαίνουν μόνο μετά από authorization check, με έλεγχο ownership, προστασία από path traversal και whitelist σε MIME type και extension.

12

RESTful API + Postman

Πώς κάναμε testing, ποια methods χρησιμοποιήσαμε και πού χρησιμοποιήθηκαν περισσότερο

Postman

Χρησιμοποιήσαμε Postman για API testing σε auth flows, enrollment actions και profile responses.

REST Methods

Υλοποιήσαμε GET, POST, PUT και DELETE, για παράδειγμα στον enrollment API controller.

Τι χρησιμοποιήθηκε περισσότερο

Περισσότερο χρησιμοποιήθηκαν GET και POST για retrieval και submit actions, ενώ PUT και DELETE κάλυψαν update και remove flows.

Session + Role check

Σε κάθε request γίνεται έλεγχος session και role πριν εκτελεστεί οποιαδήποτε sensitive λειτουργία.

API endpoints που δείχνουμε live

  • api/applications.php: αιτήσεις candidate με GET και POST actions
  • api/enrollment.php: LMS access και sync με GET, POST, PUT, DELETE
  • api/profile.php: profile, password και avatar actions
  • api/notifications.php: mark-as-read action για admin notifications
